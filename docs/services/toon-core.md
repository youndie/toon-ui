# toon-core

## 1. Responsibility

The library module: everything a consumer of toon-ui depends on. Today it is the build and nothing
else. It compiles for Android, iOS (`iosArm64`, `iosSimulatorArm64`), desktop JVM and wasmJs, and its
desktop test suite composes off-screen (B-01). Tokens, geometry, drawing primitives, icons, FX and the
components land here item by item (backlog stages 0–2).

The bundled fonts are here too (B-02): `type/ToonFontFamilies.kt` gives each theme a display and a
body family, internal until the theme provider (B-08) exposes them.

It deliberately does **not** depend on any Material artefact (research D2). It holds no sample app
and no design references; those get modules or directories of their own when their items arrive.
It is not published yet (B-32).

## 2. API contracts

No public API yet. Packages are `io.github.youndie.toon.*` (research D1).

## 3. How it is built

The build is oldge-ui's, cut down to one module. `io.github.youndie.sborka.settings` supplies the
repositories and the `wip` version catalog, so the Kotlin compiler, AGP and Compose Multiplatform
versions are a sborka bump, never a line here. `sborka.kmp` sets the toolchain and compiler flags,
warnings-as-errors included. `sborka.lint` runs ktlint against the portfolio's `.editorconfig`.

The AGP KMP library plugin is declared, unapplied, in the root build. The Compose plugin can only see
AGP's extension types when both are in the same build classloader. oldge-ui and kvadrant-ui each met
this once.


On this mac, not on the Linux box: the project is not in `mutagen sync list`, and the screenshot
goldens to come are a claim about the mac's rasteriser. `check` also runs the iOS simulator tests,
so Xcode's simulator runtime has to be installed. `local.properties` names the Android SDK; it is
not committed.

## 8. Quirks

- `compileIosMainKotlinMetadata` and its two siblings compile without warnings-as-errors. CMP 1.12
  brings two lifecycle klibs with one `unique_name` into the shared iOS metadata, and the loader's
  warning about it is not this module's to fix. The per-target iOS compilations keep `-Werror`.
- `./gradlew check` compiles the desktop, wasmJs and iosSimulatorArm64 main sources and runs the
  desktop tests. It does **not** compile `iosArm64` or Android main. Those are
  `:toon-core:compileKotlinIosArm64` and `:toon-core:compileAndroidMain`, run by hand in B-01 (both
  green). A change that breaks only a device target passes `check`.
- `compose.components.resources` is a deprecated accessor in the build script (two `w:` lines on
  every configuration). The plugin's own accessor keeps its version tied to the Compose plugin's,
  and oldge-ui made the same trade.
- An icon's centerline is measured enlarged 1024 times (B-11). Skia's `PathMeasure` flattens a curve
  to about half a unit, a percent of an icon's length on the 24 dp grid, and that dropped samples
  against the engine. Any later port that samples a small path along its length meets the same.
- `Toon.fx` outside a `ToonFxHost` is an emitter that drops every event, listeners included. A
  component works in a preview without a host, and nothing in it tells that its effects went nowhere.
- An effect's point defaults to where the FX page puts it on its demo block. A component that fires
  one passes the engine's own numbers, which differ per component (B-12, research D3).
- Text is measured against a floor of its own (research D3): Compose on desktop lays glyphs at whole
  pixels and Chrome on the mac at fractions, so a label drawn right still differs by about 2 % of its
  cell. The same label measures 74 dp wide here and 73.44 in Chrome.
- A component that breathes while idle (the FAB by default, a button with `idle`) asks for a frame
  every frame, so a Compose UI test that waits for idle never gets there. Such a test sets
  `mainClock.autoAdvance = false` and advances the clock itself (`ToonFabTest`), as with any infinite
  animation.
- The checkbox, the radio and the switch squash under a press to the spec pages' Pressed cells (0.86; the
  switch's thumb 1.18 × 0.84 on its bottom), which the kit does not do: its controllers act on the
  release only (B-17, B-18).
- An icon's outline and fill are built once per glyph and weight and kept in the glyph, as the engine
  caches per name and base (B-15). Two threads drawing a new glyph at once may each build it; the
  result is the same.
- A card's hole goes to the FX host when there is one (`card.gone`), else the card draws it, turned
  with the card; the host's hole is not turned (B-21).
- A list of cards — the 40 ms cascade and the close-up after a dismiss — is not built: B-46.
- A dialog is a full-screen layer: the caller puts it over the content it dims (a `Box` with both),
  and it fills its box. Closed, it takes no input, so it can stay composed (B-24).
- A dialog's pop hands its stars to a `ToonFxHost` 170 ms into the close (`dialog.pop`), which plays
  them whole; without a host the dialog draws them itself, as the kit does, and the kit stops drawing
  the close at 320 ms, when the stars are 43 % through (B-24).
- The dialog's keyboard: the layer takes the focus, Tab and the arrows move it between the buttons
  (confirm first), Enter or Space presses it, Escape cancels. The kit has none of it; the focused
  cells on the MVP page are what it draws.
- A component's canvas is drawn in dp inside `inDp` (B-47), and a label is laid out at density 1
  with the user's font scale. A new component that draws a frame, or reads a pointer's position,
  does the same: `inDp { … }` around its drawing, `position / density` in its gesture.
- The FX host draws an event's effect from its `bounds` alone; the `at`, `spread`, `size` and
  `puffs` an event carries are not read yet (B-48), so a dialog's pop is drawn above the layer's
  top edge, not on the dialog.
- An indeterminate progress indicator asks for a frame every frame for as long as it is shown, as the
  kit's global clock does; it does not take a slot of the idle budget, which is for decoration. A UI
  test with one on screen sets `mainClock.autoAdvance = false` (`ToonProgressTest`).
- The top app bar sways on a tap anywhere on it (the kit kicks on every release, on a target or
  not), on a change of `scrolled`, and on a fling of the content under it when that content takes
  `ToonTopAppBarState.nestedScrollConnection`; the kit has no fling of its own, so any fling with a
  velocity counts (B-26). The kit draws the sway for 900 ms and the bar is still after it.
- The top app bar's actions are glyphs and `onAction` gets the glyph, where the kit passes the icon's
  name; a screen reader gets each action under its glyph's name.
- The navigation bar's badge is the kit's: a dot on `badgeIndex`. The MVP page also draws a numbered
  badge and a disabled item in its cells, which the frame holds (`ToonNavLook`); neither is a prop of
  `ToonNavBar.dc.html`, so the composable has neither (B-27).
- The navigation bar's paper runs 8 dp past each side and 16 below its 80 dp box, as the kit draws it.
- The navigation bar's keyboard: it takes the focus as one control, the arrows move the ring, Enter
  or Space selects; a screen reader gets each destination as an action.
- The tabs do not move the content under them: `ToonTabsState.contentOffset` is the engine's `cx`,
  40 dp toward the new tab springing back to 0, and the caller offsets its content by it (B-28). It
  is 0 at rest and under reduce motion. The MVP page's disabled tab is drawn by the frame, not a prop.
- Cyrillic is drawn in a backing face per role (B-35), as spans of an `AnnotatedString` the frame's
  text renderer and the text field's visual transformation build; Compose has no per-glyph fallback
  between bundled families. A label in another script the design's faces lack (Greek, say) still
  falls to the platform's face.
- The Cyrillic faces are held twice: by the `Cyrillic_Sheet_*` goldens, which fail when a backing's
  scale or weight moves, and by `ToonCyrillicMetricsTest`, which says which (B-35, corrected in B-29).
- The stage's tile is chosen by the theme's stage colour (B-13): a theme of the caller's own, with
  another stage colour, gets a flat stage. The paper tiles ship with the gouache ones, as the design
  keeps them, and nothing draws them yet; the four add 0.5 MB.
- The screen references (`Screens_*`) are the Screens page itself, rendered by the design's runtime
  with reduced motion (B-29), not a scene of the engine's. Two of the page's CSS habits are modelled
  in the fixtures, not in the components: a line box shorter than the face's own line (Shrikhand
  at `line-height: 1`), centred as CSS's negative half-leading puts it, and an inline component's
  line box as tall as the page body's strut (the desktop's progress bar, 19.2 dp for 14).
- A dismissible card offers `Dismiss` as a screen reader's action, since a swipe has none (B-30); it
  throws the card as a swipe to the right does.
- The top bar's outermost action target reaches the sign's edge and the innermost 8 dp past its
  40 dp: one or two actions are 48 dp targets. A middle one of three or more stays 40 dp (B-49).
- The navigation bar and the tabs are one node each for a screen reader: the selected item as its
  state, every item as an action, not a node per item (B-30).
- The slider's keyboard and a screen reader move it one stop, or a twentieth of the rope when it
  has none (B-36); the kit has no keyboard, so the step is the library's.
- The menu is one node for a screen reader, every item an action, the selected one its state; the
  arrow keys walk the items and Enter or Space chooses (B-37), where the kit has no keyboard. Its
  first and last targets reach the scroll's edges; a middle item of three or more stays 44 dp (B-50).
- The menu is the scroll alone and does not place itself under its trigger: the caller lays it
  out. It draws outside its box while unrolling, the paper overshooting by up to 23 % (36 dp under
  three items at 144 ms), so a parent that clips cuts the overshoot.
- The bottom sheet fills its parent and its sheet runs 6 dp past either side and 40 below, as the
